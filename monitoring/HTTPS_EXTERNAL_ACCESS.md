# SCHUTZ Management Web HTTPS 접속 기록

작업일: 2026-10-24 ~ 2026-10-25

## 목적
SSM 포트 포워딩 없이 모니터링 EC2의 Management Web에 HTTPS로 접속하도록 설정.

## 구성 요약
- 기존 모니터링 EC2 및 Management Web 컨테이너 유지
- Uvicorn TLS 사용, 호스트 TCP 18001 -> 컨테이너 8000
- 서버의 별도 Compose 오버레이: `compose.management-https.yaml`
- 서버 내부 자체 서명 인증서 사용. 개인키는 GitHub에 업로드하지 않음
- 앱 설정: `ALLOWED_ORIGIN=https://<server-address>:18001`, `COOKIE_SECURE=true`
- HTTP localhost Origin 설정이 남아 있을 경우 로그인 시 CSRF_INVALID 오류 발생 가능

## 배포 유의사항
- HTTPS 오버레이를 기존 Compose 파일들과 함께 병합하여 management-web만 재생성했음
- 기존 ECR/SSM 재배포 스크립트에 오버레이가 누락되면 HTTPS 설정이 사라질 수 있음
- 실제 배포 시 서버의 검증된 Compose 원본과 병합 결과를 확인해야 함
- 장애 시험 중에는 팀원분과 조율 없이 재시작하지 말 것

## 네트워크 접근
- AWS 보안 그룹의 TCP 18001을 필요한 사용자의 공인 IPv4 /32만 허용하는 방식 권장
- 전체 공개(0.0.0.0/0)는 관리 페이지 노출 위험이 있으므로 지양
- 같은 Wi-Fi의 노트북과 휴대폰에서 페이지 접속 확인
- 모바일 데이터에서는 접속 실패. 팀원분의 다른 네트워크 접속은 아직 미확인

## 인증서 보안
- 자체 서명 인증서는 다른 기기에서 기본 신뢰되지 않음
- 안전한 경로로 인증서 지문 검증 후 신뢰 여부 결정
- 인증서 개인키, 환경변수 원본, 관리자 비밀번호, 토큰을 저장소에 올리지 말 것
- 공인 IP가 변경되면 접속 주소, 인증서, 허용 Origin 재검토

## 검증 내용
