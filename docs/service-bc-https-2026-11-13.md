# 서비스 B·C 도메인 및 HTTPS 구축 기록 (2026-11-13)

## 범위 및 근거
프로젝트 담당자의 구축·브라우저 확인 보고를 토대로 작성한 운영 기록이다. **현재 EC2에서 설정 파일을 직접 수집하거나 GitHub와 비교한 검증 기록은 아니다.** 실제 설정의 최종 백업은 별도 확인이 필요하다.

| 서비스 | 용도 | HTTPS 주소 |
| --- | --- | --- |
| B | 회사 홈페이지 | https://schutz-home.duckdns.org |
| C | 기술지원 커뮤니티 | https://schutz-community.duckdns.org |

## 수행했다고 보고된 작업
1. DuckDNS의 B·C 도메인을 서비스 EC2의 퍼블릭 IP로 연결.
2. 서비스 EC2의 Nginx 리버스 프록시에서 요청 호스트명에 따라 B와 C로 분기.
3. Let's Encrypt 인증서를 발급·적용.
4. B·C HTTPS 페이지의 브라우저 접속 확인.

## 확인 및 인수인계 체크리스트
- [ ] 현재 DNS 레코드가 실제 서비스 EC2의 퍼블릭 IP를 가리키는지 확인
- [ ] 현재 실행 중인 Nginx의 B·C 서버 블록을 검토하고 **비밀정보를 제거한 템플릿**으로 백업
- [ ] 인증서의 대상 도메인·유효기간 및 브라우저 신뢰 상태 재확인
- [ ] HTTP→HTTPS 리다이렉트 및 서비스별 라우팅 확인
- [ ] 서버 재시작·재배포 후 HTTPS 구성이 유지되는지 확인
- [ ] 인증서 갱신 정책 또는 프로젝트 종료 시 서비스 철수 절차 기록

## 주의
- 인증서 **개인키**, DuckDNS 토큰, AWS 자격 증명, 비밀번호, 원본 .env 파일은 절대 커밋하지 않는다.
- 실제 Nginx 설정 파일 내용은 이 문서에 임의로 재현하지 않았다.
- A 직원 포털의 기존 IP 기반 자체 서명 HTTPS 구성은 B·C의 Let's Encrypt 구성과 별개이다.
- 기존 `monitoring/HTTPS_EXTERNAL_ACCESS.md`는 **관리 웹**의 HTTPS 기록이며 B·C 구축 기록과 혼동하지 않는다.
